# Gemini 작업 1: 출시 전 레벨 검증 도구

아래 프롬프트를 새 Gemini 대화에 붙이고 함께 준비한 `gemini-level-validation.zip`을 첨부한다. ZIP에는 현재 로컬 소스가 포함되어 있다. GitHub의 이전 버전보다 첨부 파일을 우선한다.

```text
너는 iOS 출시를 준비하는 Godot 4 단어 퍼즐의 개발자다. 이번 작업은 레벨 검증 도구 구현이다. 첨부 ZIP의 실제 파일만 근거로 삼아라.

프로젝트 목표:
- Windows 개발 후 Mac mini에서 iOS 빌드·실기기·TestFlight를 진행한다.
- iOS 먼저, Android 나중. 무료 + IAP/IAA. 오프라인 우선, 초기 자체 서버 없음.
- 현재는 게임 규칙과 콘텐츠의 완결성을 먼저 확보한다.
- AGENTS.md와 docs/RELEASE_PLAN.md를 읽어라. 다른 프로젝트의 지침이나 HubGame 요구를 가져오지 마라.

이번에 구현할 파일:
- tools/validate_levels.py: Python 표준 라이브러리만 사용하는 독립 실행 CLI.
- docs/LEVEL_VALIDATION.md: 실행법, 판정 기준, 발견된 문제와 한계.

읽을 파일:
- godot-project/data/levels.json
- tools/level_generator.py
- web-prototype/index.html의 LEVELS 및 타일 선택 제한, 정답·보너스 판정
- godot-project/scripts/LevelController.gd

검사 요구:
1. 인자로 JSON 경로를 받고 최상위 레벨 배열, rows/cols, words, bonusWords의 타입을 검사한다.
2. 양의 정수 크기(bool 제외), 0 이상의 정수 좌표, H/V 방향, 비어 있지 않은 단어, 보드 경계를 검사한다. 잘못된 입력에 traceback 대신 이해할 수 있는 오류를 출력한다.
3. 좌표별 셀 맵을 만들고 서로 다른 글자의 교차 충돌을 단어명·좌표와 함께 오류로 보고한다. 같은 글자의 교차는 한 셀로 센다.
4. 중복 정답 단어는 오류, 중복 보너스와 정답 겸용 보너스는 경고로 보고한다. 보너스에 필요한 글자 수가 초기 보드의 고유 셀 글자 수를 초과하는지도 경고한다. 외부 사전을 쓰지 않으므로 사전적 유효성을 검증했다고 주장하지 않는다.
5. 현재 웹 입력 규칙을 실제로 읽고, 힌트 없이 정답만으로 완료 가능한지 분석한다. 현재 규칙은 남은 타일 수로 전체 단어를 입력해야 하므로, 채워진 교차 글자가 입력 불능을 만드는지 확인해야 한다.
6. 정답 제출로 채워지는 좌표 집합을 상태로 하여 탐색한다. 이미 모든 셀이 채워진 단어는 추가 제출 없이 해결된 것으로 판단한다. 초기 상태에서 전체 셀 완성에 도달하는 정답 순서가 있는지 보고한다. 유효한 정답 제출 뒤 도달 가능한 막힌 상태도 따로 보고한다. 보너스는 진행을 소모하지 않으므로 탐색에서 제외한다.
7. 구조가 잘못된 레벨은 탐색을 건너뛴다. 탐색 상태 수 상한을 두고 초과 시 미판정으로 표시한다. 미판정을 통과로 보고하지 않는다.
8. 종료 코드는 검증 완료·오류 없음=0, 오류 발견=1, 읽기/파싱/CLI 실패 또는 탐색 미판정=2로 한다. 오류와 미판정이 같이 있으면 2를 우선한다. 경고만 있으면 0이다.
9. 알려진 예: 가로 CAT(0,0), 세로 CAR(0,0)는 고유 셀이 5개다. 초기 집계 C:1,A:2,T:1,R:1은 맞지만 현행 전체 단어 입력 제한에서는 한 단어 해결 후 C 부족으로 다른 단어를 입력하지 못할 수 있다. 집계 정확성과 플레이 가능성을 구분하라.
10. 웹 인라인 LEVELS는 이번 CLI에서 임의로 정규식 파싱하지 말고, Godot JSON과의 차이가 있으면 문서에 별도로 보고하라.

범위 제한:
- 실제 게임 코드, 기존 레벨, 생성기, 재화 규칙은 변경하지 마라.
- 교차 글자 입력 문제의 해결 대안은 문서에서 2개 이내로 제안하라. 남은 타일 집계 규칙은 유지해야 한다.
- 엔진 교체, 3D, 광고, 상점, 서버, 외부 의존성, 인라인 코드 주석을 추가하지 마라.

출력:
1. 두 파일의 전체 내용을 파일 경로별로 제공하라.
2. 기본 실행 명령을 제공하라.
3. 실제 실행한 검증과 실행하지 않은 검증을 구분하라.
4. 실제 저장소 데이터를 확인하지 못했다면 코드를 추측하지 말고 알려라.
```

# iOS 우선 출시 개발 기준

## 목표와 협업

2026-11-17 확정한 v1 수량·언어·초기 경제·1~9 진행 게이트는 `LAUNCH_SCOPE.md`, 비주얼 방향·에셋 명세는 `VISUAL_DIRECTION.md`를 따른다. 범위의 확정과 구현·실기기 검증 완료는 구분한다.

- 무료 설치, IAP(인앱 구매)와 IAA(광고)를 함께 사용하는 캐주얼 단어 퍼즐을 출시한다.
- Windows에서 게임, 콘텐츠, 저장, UI와 플랫폼 연동 계층을 개발한다. Mac mini에서 iOS 플러그인 링크, 서명, 실기기, Sandbox 결제, 광고, TestFlight를 검증한다.
- 무거운 구현과 콘텐츠 생성은 사용자가 Gemini에 프롬프트와 최신 소스를 전달한다. Codex는 작업 선정, 검토, 통합, 검증을 맡는다.
- 수익과 리텐션은 가설로 관리한다. 플레이 테스트 결과를 바탕으로 난이도, 보상, 광고 빈도를 조절한다.

## 기술 방향

- 기존 Godot 4 프로젝트를 모바일 앱의 우선 후보로 유지한다. 웹은 빌드 없는 규칙 검증용 프로토타입이다.
- Godot 버전과 네이티브 플러그인은 iOS/Android 지원, 유지보수 상태, 라이선스와 재현 가능한 빌드를 확인한 뒤 고정한다. 현재 설정의 4.2 표기를 출시 버전 확정으로 간주하지 않는다.
- iOS IAP는 StoreKit, 광고는 AdMob 등을 후보로 검토한다. 실제 Godot 플러그인의 지원 API와 버전을 확인하기 전에는 연동 구현을 확정하지 않는다.
- 플랫폼 기능은 게임 로직과 분리한다. Windows 테스트용 모의 구현과 iOS/Android 실제 구현을 나누되 출시 빌드에서 모의 구매·광고 보상을 지급하지 않는다.
- HubGame, 자체 계정, 자체 서버, Firebase를 초기 필수 의존성으로 두지 않는다.

## 첫 출시 범위

1. 짧은 튜토리얼, 납득 가능한 단어와 교차 배치, 충분한 검증된 레벨, 난이도 곡선.
2. 정답·힌트·보너스·클리어 보상, 중복 지급 방지, 저장 복원, 설정, 안전 영역 대응.
3. 상점: 광고 제거 비소모성 상품, 소수의 코인 소모성 상품을 초기 후보로 한다. 실제 상품 ID, 가격, 재화 지급량은 별도 확정한다.
4. 광고: 선택형 보상 광고를 우선하고 전면 광고는 스테이지 사이에 빈도 제한과 초기 유예를 둔다. 플레이 입력 중에는 노출하지 않는다. 배너는 초기 필수 범위에서 제외한다.
5. 광고 제거 상품이 제거하는 광고 범위를 구매 전에 명확히 표시한다. 선택형 보상 광고 유지 여부도 상품 설명과 일치시킨다.
6. 리텐션: 오프라인 일일 퍼즐, 일일 목표, 가벼운 수집/테마 해금부터 검증한다. 시간 조작 가능한 오프라인 보상은 경쟁 순위나 현금 가치와 연결하지 않는다.
7. Game Center는 플레이 테스트에서 경쟁 또는 업적의 가치가 확인되면 추가한다. 첫 출시의 필수 차단 조건으로 두지 않는다.

## 비용과 서버 없는 운영의 경계

- 초기 권장 구성은 로컬 저장 + Apple IAP + 광고 SDK다. 자체 서버의 고정 운영비를 피할 수 있다.
- Apple Developer Program은 통상 연 US$99 또는 현지 가격이다. 가입 시점의 공식 가격, 면제 자격, 세금 등을 확인한다. App Store 수수료는 별도이며 프로그램 자격과 거래 조건에 따라 달라진다.
- Game Center는 보통 별도 사용량 과금 없이 Apple 개발자 생태계에서 이용한다. 도입 시 최신 조건을 확인한다. Android 전환 시 Google Play Games를 별도 어댑터로 검토한다.
- Firebase 무료 한도는 기능과 사용량에 따라 다르며, 기능에 따라 결제 계정이 필요하다. 초기에는 도입하지 않고 원격 설정·분석·교차 플랫폼 저장의 실측 필요가 생길 때 검토한다.
- 서버가 정말 필요해지면 필요한 기능만 무료 한도에서 시작한다. 그다음 실제 요청량·저장량·전송량으로 비용을 비교한다. 가격 알림은 강제 과금 상한이 아니므로 쿼터·레이트 제한도 설계한다.
- 로컬 저장만으로는 재설치 후 진행도와 소모성 코인을 복원한다고 보장할 수 없다. 비소모성 구매 복원과 게임 진행도 복원은 별개다. 출시 전 사용자 안내와 복구 정책을 확정한다.
- 서버 없는 구매는 거래 식별자 기반 중복 지급 방지와 플랫폼 검증을 사용하되 기기 변조·재설치·환불 악용에 대한 한계가 있다. 경쟁 순위와 재화에 대한 강한 부정행위 방지는 추가 서비스가 필요할 수 있다.
- 위 금액과 서비스 조건은 계획용 기준이며 이번 작업에서 최신 요금표를 조회해 확정한 값은 아니다.

공식 확인처: [Apple 개발자 등록](https://developer.apple.com/programs/enroll/), [Small Business Program](https://developer.apple.com/app-store/small-business-program/), [Game Center](https://developer.apple.com/game-center/), [Firebase 요금](https://firebase.google.com/pricing), [AdMob 개인정보 도구](https://developers.google.com/admob/ios/privacy).

## 단계와 완료 기준

### 1. 규칙과 콘텐츠 검증

- 좌표 범위, 방향, 교차 글자 일치, 단어 중복, 보너스 유효성을 자동 검사한다.
- 남은 셀 기준 타일 수를 유지하면서 이미 채워진 교차 글자가 있는 단어도 입력·완성할 수 있는지 검증한다. 현행 입력 제한과의 충돌은 별도의 명시적 규칙 결정으로 해결한다.
- 유료 재화나 광고 없이 모든 레벨을 끝낼 수 있어야 한다.

### 2. Godot 플레이 가능한 기본 버전

- 현재 누락된 MainGame, LetterTile, BoardCell 씬과 컨트롤러를 완성한다.
- 마우스·터치 입력, 보드, 랙, 저장 복원, 힌트, 보너스, 보상, 다음 레벨을 연결한다.
- 웹과 Godot의 게임 규칙을 맞추고 Godot 실행 검증을 통과한다.

### 3. 리텐션과 콘텐츠

- 튜토리얼, 레벨 배치, 난이도, 일일 콘텐츠, 테마와 피드백을 구현한다.
- 첫 세션 이탈, 레벨 완료율, 힌트 사용, 다음날 재방문을 플레이 테스트 또는 개인정보 요건에 맞는 분석으로 평가한다.
- 대상 연령과 출시 언어·지역을 확정한다. 사전의 사용·배포 라이선스를 확인한다.

### 4. 상점과 광고

- 구매의 성공·취소·보류·실패, 복원, 재시작, 중복 콜백을 처리한다. 지급 완료를 기록한 뒤 플랫폼 거래를 완료 처리한다.
- 광고 없음·실패·닫기·오프라인 상태에서도 게임 진행을 유지한다. 보상은 SDK의 유효한 보상 콜백에만 한 번 지급한다.
- 개인정보 동의, 추적을 사용하는 경우 ATT, SDK 개인정보 매니페스트, 지역·연령별 광고 정책을 점검한다.

### 5. Windows 작업 완료 / Mac 인계

- 게임과 콘텐츠 자동 검사, 저장 마이그레이션, UI 크기별 점검, 모의 결제·광고 테스트를 완료한다.
- 플러그인 소스·버전·설치법과 빌드 절차, 상품·광고 ID 설정 위치, 알려진 미검증 사항을 문서화한다. 인증서·키·비밀값은 저장소에 넣지 않는다.
- App Store 설명, 스크린샷 계획, 지원·개인정보 URL, 데이터 수집 내역, 구매 복원 안내를 준비한다.
- 이 단계는 네이티브 출시 검증 완료를 뜻하지 않는다. iOS 플러그인·결제·광고 검증에는 Mac과 실제 기기가 필요하다.

### 6. Mac 및 후속 Android

- Mac: Xcode export/서명, 실기기 안전 영역·성능·오디오·중단 복귀, Sandbox 구매/복원, 광고 테스트 ID, 동의 흐름, Game Center를 채택했다면 실인증을 검증하고 TestFlight로 배포한다.
- Android: 공통 게임 코드를 유지하고 Google Play Billing, 광고·동의, 선택적 Play Games 연동을 교체하여 내부 테스트부터 진행한다.

## 현재 확인한 출발점

- 웹의 클리어 보상 중복 방지와 힌트 클리어 처리, Godot의 교차 셀 집계는 수정되었다.
- Godot의 메인 씬과 셀·타일 씬, 컨트롤러를 연결해 기본 3개 레벨을 플레이할 수 있다. 오프라인 일괄 저장, 클리어 보상 복원, 입력과 실패 처리를 실제 엔진에서 검증했다.
- 초기 레벨의 교차 충돌을 수정하고 정답 접두사 재사용 규칙을 웹·Godot에 적용했다. 실기기 터치와 모바일 네이티브 기능 검증은 필요하다.
- Windows 다운로드 폴더의 Godot 4.7.2 ZIP을 로컬 dist에 추출해 실제 임포트·회귀 검사·375/480 너비 렌더링을 확인했다. 상세 범위는 `GODOT_PLAYABLE.md`를 따른다.

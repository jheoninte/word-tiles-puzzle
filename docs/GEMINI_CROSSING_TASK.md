# Gemini 작업 2: 교차 글자 재사용과 레벨 정상화

아래 프롬프트와 `gemini-crossing-input.zip`을 새 Gemini 대화에 전달한다. 이 ZIP의 로컬 최신 코드를 기준으로 작업하며 GitHub의 이전 소스를 섞지 않는다.

```text
첨부 ZIP의 Word Tiles 단어 퍼즐을 실제로 읽고 다음 기능을 구현하라.
이번 작업의 목적은 광고·힌트·과금 없이 정답을 맞혀 모든 기본 레벨을 완성할 수 있게 하는 것이다.

근거 파일:
- AGENTS.md
- web-prototype/index.html
- godot-project/scripts/LevelController.gd
- godot-project/scripts/SwipeRackController.gd
- godot-project/scripts/LetterTile.gd
- godot-project/data/levels.json
- tools/validate_levels.py
- docs/GAME_DESIGN_SPEC.md 및 docs/LEVEL_VALIDATION.md

확인된 문제:
- CAT 가로(0,0), CAR 세로(0,0)는 고유 셀 5개지만 CAT을 맞힌 뒤 C가 0개가 되어 CAR를 입력하지 못한다.
- 레벨 1의 RAT 시작 행이 1이어서 EAR와 충돌한다. RAT의 r만 2로 옮기면 기존 단어를 유지하면서 충돌을 피할 수 있다.
- 레벨 3의 RING 시작 행이 3이어서 MARS와 충돌한다. RING의 r만 2로 옮기면 된다.
- 카페 레벨 등 일부 보너스는 초기 보드에 필요한 글자가 없다.

A. 확정할 입력 규칙
1. 표시 타일 수와 recalcTileCounts()/recalculate_tile_counts()의 의미는 그대로 미완성 고유 셀 개수다. 채워진 셀을 집계에 다시 넣지 마라.
2. 선택 문자열이 남은 타일 수만으로 구성 가능하면 기존처럼 입력을 허용한다.
3. 수량을 초과하더라도 선택 문자열이 미완성 정답 단어 하나 이상의 접두사라면 입력을 허용한다. 이를 통해 이미 채워진 교차 글자 또는 힌트 글자를 다시 입력할 수 있다. 해당 정답의 남은 셀 수와 채워진 셀의 합이 전체 단어 수량을 보장한다.
4. 매 글자 추가 시 전체 선택 문자열을 다시 검사한다. 예외 허용을 받은 뒤 잘못된 접미사를 붙여도 계속 입력되는 허점을 막는다.
5. 정답 제출은 미완성 정답과 전체 문자열이 일치할 때만 성공한다. 이미 해결된 정답에 중복 보상을 주지 않는다.
6. 보너스는 반드시 현재 미완성 셀의 수량만으로 전체 문자열을 만들 수 있을 때만 지급한다. 정답 접두사 예외를 이용해 수량 부족 보너스를 받으면 안 된다. 이미 받은 보너스 중복 지급도 막는다.
7. 랙의 선택 가능 상태는 이 규칙과 일치해야 한다. 0개여도 정답 재입력에 쓸 수 있는 글자는 선택 가능하게 하되 숫자는 0으로 남기고 재사용 표시를 작게 구분한다. 뱃지는 음수가 되면 안 된다. 사용자에게 표시하는 수량에 허용량을 섞지 마라.
8. 힌트·레벨 전환·로드 등 보드 상태 변경 시 선택 상태를 안전하게 초기화한다. 이전 DOM 타일 참조, 드래그 상태, 지연 clearSelection 타이머가 다음 입력에 영향을 주지 않도록 최소한으로 처리한다.

B. 웹 구현
- 수량 검증과 접두사 예외 판정을 별도 순수 함수 또는 작은 함수로 분리해 addTileSelection, refreshRackVisuals, 보너스 제출이 같은 규칙을 사용하게 한다.
- 기존 공개 함수와 저장 키, rewardClaimed 기반 클리어 보상, 힌트 비용과 보너스 보상을 유지한다.
- 모바일 스와이프와 기존 입력 방식을 유지한다. HTML 파일은 빌드·외부 라이브러리 없이 실행되어야 한다.
- 웹 인라인 LEVELS와 Godot JSON의 단어 배치 및 보너스 내용을 맞춘다. 배열 순서·difficulty 필드 차이는 허용한다.

C. Godot 구현
- LevelController에 새 공개 헬퍼 can_select_text(text: String) -> bool 및 can_submit_bonus(text: String) -> bool을 추가하여 웹과 같은 판정을 제공한다.
- 기존 공개 함수명·인자·반환을 유지한다.
- SwipeRackController에 선택적으로 LevelController를 연결할 수 있게 하되 기존 신호 및 append_letter/submit/clear_selection 인터페이스는 유지한다. 연결된 경우 선택 전 헬퍼로 검사한다. 선택 초기화 신호 흐름도 유지한다.
- LetterTile은 기존 setup_tile/set_remaining 인터페이스를 유지하며 수량과 별도로 선택 가능 여부를 전달하는 선택적 메서드를 추가한다. 호출자가 재사용 가능 상태를 지정하면 0개여도 tile_selected를 보낼 수 있어야 한다. 기본 동작은 기존 수량 제한이다.
- 아직 MainGame.tscn과 실제 씬 연결은 없다. 이번 작업에서 씬 전체를 새로 만들지 말고 추가한 연결법을 짧게 문서화한다. Godot 플레이가 완성됐다고 주장하지 마라.

D. 데이터와 검증기
- 위의 최소 좌표 변경을 웹·Godot 양쪽에 적용한다.
- 초기 고유 셀 수량으로 만들 수 없는 보너스와 정답 겸용·중복 보너스를 제거한다. 새 사전이나 새 레벨을 대량 생성하지 않는다.
- tools/validate_levels.py의 기본 탐색 판정을 새 입력 규칙과 맞춘다. 기존 파일 인자와 --max-states를 유지하고 --input-rule crossing-reuse|remaining-only 옵션을 추가한다. 기본은 crossing-reuse, 구규칙은 회귀 비교용이다.
- 새 규칙에서도 2글자 이상 제출, 이미 채운 좌표의 단어 자동 해결, 탐색 상한, 잘못된 타입 검사, 종료 코드 0/1/2와 미판정 우선순위를 유지한다. 탐색을 건너뛰고 무조건 통과시키지 마라.
- docs/GAME_DESIGN_SPEC.md와 docs/LEVEL_VALIDATION.md에 새 규칙, 보너스 예외 금지, Godot 헬퍼 연결법, 실제 검증 결과 또는 미검증을 반영한다.

필수 확인 사례:
1. CAT 이후 CAR, CAR 이후 CAT이 모두 힌트 없이 성공한다. 첫 단어 후 C 수량은 0이며 전체 완료 후 타일 합은 0이다.
2. 0개 C를 선택해 CAR로 이어갈 수 있지만 CX처럼 유효한 정답 접두사를 벗어나는 수량 초과 문자열은 거부한다.
3. 힌트로 C를 먼저 채운 상태와 저장 복원 뒤에도 CAT/CAR를 입력할 수 있다.
4. 재사용 예외를 이용한 수량 부족 보너스는 거부하고 정상 보너스는 한 번만 지급한다.
5. 다음 레벨과 마지막 레벨 버튼, 새로고침 중복 보상 방지에 회귀가 없다.
6. 새 규칙에서는 수정한 기본 레벨이 구조 오류·플레이 불능·막힌 상태 없이 통과한다. 구규칙에서는 CAT/CAR가 실패한다. 타입 오류와 탐색 상한은 기존 종료 코드를 유지한다.

범위:
- 위의 파일 중 필요한 파일만 변경하라. 일반 리팩터링, 프로젝트 교체, 웹 전체 재작성은 금지한다.
- 외부 문서의 스튜디오 규칙을 이 프로젝트 요구로 가져오지 마라. HubGame, 클라우드, 리더보드, 광고, 상점, 3D 기능은 이번 요청에 없다.
- 인라인 코드 주석을 추가하지 마라. 필요한 설명은 Markdown 문서에 쓴다.

출력:
- 변경 파일만 정확한 경로와 생략 없는 전체 코드로 제공한다. Markdown 문서도 포함한다.
- 실행 검증과 미검증을 구분한다. 실제 Godot 실행을 못 했으면 명시한다.
- 첨부 파일을 읽지 못하면 실제 구현을 추측하지 말고 알려라.
```

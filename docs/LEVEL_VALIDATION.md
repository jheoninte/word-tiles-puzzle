# 레벨 검증

## 실행

Python 3 표준 라이브러리만 사용한다. 프로젝트 루트에서 실행한다.

```powershell
python tools/validate_levels.py godot-project/data/levels.json
python tools/validate_levels.py godot-project/data/levels.json --max-states 10000
python tools/validate_levels.py godot-project/data/levels.json --input-rule remaining-only
```

- 종료 코드 0: 구조 오류가 없고 정답만으로 완성 가능한 순서를 찾았으며 탐색을 완료했다. 경고가 있을 수 있다.
- 종료 코드 1: 구조 오류 또는 정답만으로 완성할 수 없는 레벨을 발견했다.
- 종료 코드 2: 파일 읽기·JSON 파싱·CLI 오류 또는 상태 탐색 상한으로 미판정이다. 다른 레벨에 오류가 있어도 미판정이 우선한다.
- 레벨 번호는 1부터, 셀 좌표는 0부터 표시한다. 코드는 데이터를 변경하지 않는다.

## 판정 범위

최상위 레벨 배열, 필수 크기·단어·보너스 배열의 타입, 좌표·방향·범위, 교차 글자 충돌, 중복 정답을 검사한다. 크기와 좌표의 boolean 값은 정수로 인정하지 않는다. 같은 글자의 교차 칸은 한 셀로 센다.

중복 보너스, 정답과 같은 보너스, 초기 고유 셀 글자 수로 입력 불가능한 보너스는 경고다. 구조 오류가 있으면 잘못된 셀 집계를 근거로 보너스 수량이나 플레이 가능성을 판단하지 않는다. 외부 사전을 사용하지 않으므로 단어의 사전적 유효성과 라이선스는 별도 검수해야 한다.

탐색 상태는 이미 채운 좌표 집합이다. 기본 `--input-rule crossing-reuse`는 웹의 접두사 예외를 반영한다. 미완성 정답 전체는 자기 자신의 접두사이므로 남은 수량이 부족해도 정답 제출이 가능하다. `--input-rule remaining-only`는 예외 없이 남은 셀 글자 수만 사용하는 이전 규칙과 비교한다. 두 규칙 모두 2글자 미만 입력은 제출하지 않으며 이미 모든 셀이 채워진 단어는 별도 입력 없이 해결된 것으로 본다. 보너스에는 접두사 예외를 적용하지 않는다.

완성 순서가 있으면 예시를 출력한다. 완성 순서가 있어도 다른 유효한 정답 순서에서 막힐 수 있으므로 도달 가능한 막힌 상태를 계속 찾고 예시를 경고한다. 막힌 상태 경고가 있는 레벨은 자동 검사 종료 코드가 0이어도 출시 콘텐츠로 승인하지 않는다. 탐색 상한은 시작 상태를 포함해 등록하는 상태 수이며 기본 1,000개다. 일부 경로를 생략하면 미판정으로 보고하고 통과 처리하지 않는다.

힌트·보너스·광고·과금 없이 정답만 제출하는 논리 검증이다. 터치 제스처, 렌더링, 난이도, 재미, 힌트 사용 뒤의 모든 상태를 검증하는 도구는 아니다.

## 기존 문제와 적용한 수정

- 레벨 1: RAT 시작 행을 1에서 2로 옮겨 EAR와의 교차 글자를 R로 맞췄다.
- 레벨 3: RING 시작 행을 3에서 2로 옮겨 MARS와의 교차 글자를 R로 맞췄다.
- 레벨 2의 기존 입력 규칙은 완성 가능한 순서가 없었다. 정답 접두사 재사용으로 이를 해결한다.
- 초기 수량으로 입력할 수 없는 보너스 `라디오`, `마디`, `SUN`을 제거하고 가능한 기존 보너스는 유지했다.
- 웹은 인라인 `LEVELS`, Godot은 JSON을 사용한다. 이번 도구는 JSON만 읽으며 웹 배열을 추출하거나 두 데이터가 같다고 보장하지 않는다. 현재 양쪽은 보너스 배열의 순서와 Godot 전용 difficulty 필드가 다르다.

## 적용한 입력 규칙

미완성 정답의 접두사라면 수량을 초과한 입력을 허용한다. 랙 숫자는 계속 미완성 셀 기준이며 입력 때마다 전체 문자열을 검사한다. 정답과 무관한 문자열로 확장할 때는 전체 문자열이 남은 수량 내에 있어야 한다. 보너스 지급은 예외 없이 남은 수량만 검사한다. Godot 헬퍼와 랙 연결법은 GAME_DESIGN_SPEC.md에 기록한다.

되돌리기만으로는 CAT/CAR처럼 모든 순서가 막히는 교차 퍼즐을 해결할 수 없다. 규칙 선택과 실제 게임 수정은 후속 작업이다.

## 실행 검증과 미검증

- 이전 데이터·규칙의 실행 결과는 오류 3개, 경고 3개, 종료 코드 1이었다. 수정된 데이터와 새 규칙의 실행 결과는 아래 후속 검증 기록에 남긴다.
- 정상 단어, CAT/CAR의 고유 셀 집계와 완성 불능, 완성 경로와 막힌 경로가 함께 있는 ABA/AB, 한 글자 입력 제한, 탐색 상한의 경계값을 실행 검증했다.
- 잘못된 레벨·단어·보너스 타입, boolean/음수 좌표, 방향, 범위, 중복 정답, CLI 종료 코드, JSON 파싱 실패, UTF-8 BOM, 파일 누락, 오류와 미판정의 우선순위를 실행 검증했다.
- 브라우저·Godot 엔진 실행, 모바일 터치, iOS/Android 실기기, 외부 사전, 레벨 생성기의 대량 출력은 이번 작업에서 검증하지 않았다.

### 교차 재사용 통합 후 검증

- 기본 3개 레벨은 새 규칙에서 각각 16/8/8개 상태를 탐색했고 오류 0, 경고 0, 미판정 없음, 종료 코드 0이다.
- CAT/CAR는 새 규칙에서 완성 가능하며 `remaining-only`에서는 완성 불능과 막힌 상태를 검출한다. 기존 타입 검사, CLI 옵션, 탐색 상한과 종료 코드 우선순위도 재검증했다.
- 실제 웹 스크립트를 Node VM과 모의 DOM으로 실행했다. CAT/CAR 양방향, 0개 글자 재사용 표시, 잘못된 접두사 거부, 보너스 수량·중복 지급 방지, 힌트·저장 복원, 지연 초기화 타이머 취소, 포인터 취소, 탭·스와이프·키보드 제출을 검사했다.
- 웹의 3개 기본 레벨에서 총 36개 정답 순서의 완성과 다음 레벨 이동을 확인했다. 마지막 칸 힌트 보상, 이전 저장의 rewardClaimed 호환, 오프라인 저장 유지, 웹·Godot 레벨 데이터 일치도 검사했다.
- 모의 DOM 검증은 실제 브라우저 렌더링과 터치 검증을 대체하지 않는다. 이후 Godot 씬 연결과 실제 엔진 검증을 진행했으며 현재 범위는 `GODOT_PLAYABLE.md`에 기록한다.

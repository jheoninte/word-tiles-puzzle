# Godot 플레이 가능한 기본 버전

## 실행

Godot에서 `godot-project/project.godot`을 열고 F5로 실행한다. 외부 플러그인·네트워크·에셋 다운로드는 필요하지 않다.

```powershell
godot --editor --path godot-project
godot --path godot-project
godot --headless --path godot-project --editor --import --quit
```

이 PC에서 확인한 엔진은 다운로드 폴더의 배포 ZIP에서 추출한 Godot **4.7.2 stable**이다. 로컬 실행 파일은 `dist/godot-runtime/Godot_v4.7.2-stable_win64_console.exe`이며 위 명령의 `godot` 대신 사용할 수 있다. `dist/`와 `.godot/` 캐시는 Git에 포함하지 않는다. 4.2 계열 API를 기준으로 작성했지만 실제 4.2 엔진으로는 아직 검증하지 않았다. 생성된 `.uid` 파일은 Godot 리소스 식별 메타데이터다.

## 노드 구조

```text
MainGame (Control, MainGame.gd)
  LevelController (Node)
  SwipeRackController (Node)
  GameAudio (Node)
  Background (ColorRect)
  SafeMargin (MarginContainer)
    Scroll (ScrollContainer)
      Content (VBoxContainer)
        헤더 / 보드 / 입력 버튼 / 상태 / 랙 / 동작 버튼 / 정답·보너스 목록
```

Content의 UI는 `_build_ui()`에서 생성한다. 보드 셀은 `BoardCell.tscn`, 글자 버튼은 `LetterTile.tscn`을 사용한다. BoardCell의 `setup_cell(row,col,char,filled)`는 트리에 추가되기 전에 호출해도 안전하게 처리하고 `_ready()`에서 표시를 적용한다.

`SwipeRackController.word_changed`는 입력·랙 표시만 갱신한다. `word_submitted`는 정답/보너스를 판정하고, 셀·보상 상태를 갱신한 다음 UI를 갱신하고 한 번의 스냅샷을 저장한다. 렌더링과 저장 복원은 보상을 지급하지 않는다.

## 입력과 게임 규칙

- 마우스 클릭/터치 탭으로 글자를 고른 뒤 제출 버튼 또는 현재 단어 버튼을 누른다. 키보드로 글자 버튼에 포커스하고 활성화할 수도 있다.
- 첫 타일에서 드래그해 다른 타일을 지나 릴리스하면 제출한다. 같은 글자를 연속 입력하려면 랙 밖의 빈 곳으로 나갔다가 같은 타일로 돌아온다. 탭을 반복해 같은 글자를 선택하는 방법도 가능하다.
- 터치 원본을 게임 입력으로 처리하고 터치에서 에뮬레이션된 마우스 이벤트는 랙에서 무시한다. 일반 UI 버튼에는 Godot의 터치→마우스 에뮬레이션을 유지한다.
- 포커스 상실·터치 취소·힌트·레벨 이동 때 선택과 활성 포인터를 초기화한다. 제스처 중 랙 노드를 재생성하지 않는다.
- 수량은 미완성 고유 셀 기준이며 미완성 정답의 접두사에는 재사용을 허용한다. `↻` 표시와 숫자는 별도다. 보너스는 실제 남은 수량만 사용하고 중복 지급하지 않는다.
- 정답 보상 `max(10, 길이*5)`, 보너스 15코인, 힌트 비용 30코인, 최초 클리어 보상 30코인은 웹과 같다. 마지막 칸을 힌트로 열어도 클리어 보상을 한 번 지급한다.
- 완성되지 않은 보드와 마지막 레벨에서는 다음 이동을 차단한다.

## 저장과 복구

글자 랙은 3~4종이면 2열, 5~9종이면 3열, 10종 이상이면 4열을 기본으로 가운데에 배치한다. 따라서 5~6종은 2줄, 7~9종은 3줄이다. 1~2종은 있는 글자 수만큼 한 줄에 둔다. 좁은 화면에서는 열 수를 줄여 잘림을 피한다. 타일 수량이나 선택 순서 규칙은 바꾸지 않는다. 웹 프로토타입도 같은 기본 열 수를 사용한다.

기존 GameManager와 `user://word_tiles_save_v1.cfg`를 유지한다. 기존 함수·신호에 `commit_progress(...) -> Error`, `save_failed(error)`, 저장·로드 오류 상태 필드를 추가했다.

`[progress]`의 기존 `level_idx`, `coins`, `sound_enabled`, `filled_coords`, `bonus_words`와 함께 boolean `reward_claimed`를 저장한다. 이전 저장에 이 키가 없으면 복원한 보드의 완성 상태로 판정한다. 완성된 저장을 열었다는 이유로 코인을 추가하지 않는다.

정답·힌트·보너스·레벨 전환은 메모리에서 모든 필드를 먼저 갱신한 뒤 `commit_progress()`를 한 번 호출한다. ConfigFile을 `.tmp` 파일로 저장하고 기존 저장으로 rename한다. 실패 시 `data_saved`를 보내지 않고 이전 저장을 유지하며 UI에 실패 메시지를 표시한다. 실패 중에도 메모리에서는 플레이를 계속하고 다음 저장 시 재시도한다. 메모리 상태의 강제 종료 시 유실까지 막는 서버 저장은 아니다.

잘못된 스칼라·배열 타입은 기본값 또는 유효 항목만 사용한다. 범위 밖 레벨은 범위 내로 보정하되 해당 레벨의 이전 좌표·보너스는 재사용하지 않는다. 보드에 없는 좌표는 제외한다. 포커스 상실·앱 일시정지·창 종료 요청 시에도 저장한다.

`GameAudio`는 16-bit mono PCM 효과음 10종과 재생 플레이어 4개를 제공한다. 기존 6개 게임 효과음에 버튼·재화·보상·안내 큐를 추가했다. 48초 배경음 WAV, 음악·효과음 독립 토글/음량, 전체 음소거와 중단 사유별 복귀를 연결했다. 생성법·실제 연결 범위·설정 저장·검증 한계는 `AUDIO.md`를 따른다.

## 실행한 검증

- Godot 4.7.2 헤드리스 에디터에서 실제 스크립트·씬 임포트를 수행했다.
- 실제 게임 저장과 분리된 `Word Tiles Codex QA` 프로젝트에서 Godot 엔진 회귀 검사를 실행했다.
- 3개 레벨 진행과 최종 완료, 미완성 이동 차단, 보상 중복 방지, 저장된 좌표·재화·완료 플래그의 일관성, 완료 저장 복원을 확인했다.
- CAT→CAR 및 CAR→CAT, 수량 0의 C 재사용, 잘못된 접두사 거부, 보너스 수량과 중복 지급 방지, 탭·합성 터치 스와이프·에뮬레이션 중복 차단·포커스 상실 처리를 확인했다.
- 코인 부족, 마지막 칸 힌트, 완료 후 힌트, 이전 저장·잘못된 좌표/배열, 저장 실패를 의도적으로 만든 경우의 오류 표시와 기존 파일 보존을 확인했다.
- 375×667, 480×854에서 가로 최소 크기와 코인 한 줄 표시를 확인했다. NVIDIA GTX 1650 / OpenGL Compatibility 렌더러로 두 크기의 실제 화면을 캡처해 확인했다. 작은 세로 화면의 하단 내용은 전체 화면 스크롤로 접근한다.
- 레벨 검증기는 기본 3개 레벨에서 오류 0, 경고 0이다.
- 효과음 추가 후 Godot 4.7.2에서 6개 PCM 스트림의 길이·진폭·경계값, 재생 풀, 음소거·재활성화, 알 수 없는 큐 무시, 설정 복원·저장을 실행 검증했다. 기존 게임 회귀 검사도 통과했다. Dummy 오디오 드라이버 검사이므로 실제 스피커 청취·iOS 오디오 세션 품질을 확인했다는 뜻은 아니다.

로컬 검사·미리보기 파일은 `dist/godot-playable-smoke.gd`, `dist/godot-smoke.log`, `dist/godot-preview-375.png`, `dist/godot-preview-480.png`에 있다. QA 프로젝트와 엔진도 dist에 있으며 배포 파일에는 넣지 않는다.

## 미검증과 후속 작업

- 실제 손가락 제스처, 여러 손가락 간섭, 장시간 플레이와 기기별 앱 중단/종료는 실기기에서 추가 확인한다. 자동 검사의 터치는 합성 이벤트다.
- iOS/Android의 안전 영역·회전·터치·성능, Mac의 iOS export·서명·TestFlight는 아직 검증하지 않았다. 모바일 안전 영역은 화면 좌표를 viewport 좌표로 바꿔 마진에 반영하는 구조다.
- 실제 IAP·광고·Game Center 및 분석 SDK는 아직 없다. 웹이나 Godot에 HubGame 의존성을 추가하지 않았다.
- 첫 실행 튜토리얼·건너뛰기 저장·도움말 재생은 구현 및 Windows 엔진 검증을 완료했다. 단계, 기존 저장 호환, 화면 확인과 미검증 범위는 `ONBOARDING.md`를 따른다.
- 실제 효과음 청취와 볼륨 조정, 난이도 곡선·콘텐츠 확대, 추가 저장 버전 마이그레이션과 출시 품질의 UI 개선은 후속 작업이다.

현재 기본 화면에서 미완성 정답을 숨기고 완성한 단어와 남은 수를 표시한다. `show_debug_answers`는 기본 false이며 디버그 빌드에서 명시적으로 켰을 때만 미완성 정답을 보여준다. 출시 수량·세 언어·경제/광고 기준안과 단계별 상태는 `LAUNCH_SCOPE.md`를 따른다. 설정 UI의 세 언어 번역과 작은 화면 고정 조작 배치는 아직 후속 작업이다.

# Word Tiles - Game Design Spec

## 코어 루프
1. 보드의 빈 칸 구조를 관찰한다.
2. 하단 타일 랙에서 글자를 스와이프해 단어를 만든다.
3. 정답 단어면 보드 칸이 채워지고, 보너스 단어면 코인을 획득한다.
4. 획득 코인으로 힌트를 사용하며 다음 레벨로 진행한다.

## 핵심 시스템

### 1. 타일 수량 규칙
- 각 글자의 수량은 "남은 빈 칸" 기준으로 계산한다.
- 이미 채워진 교차 칸은 다시 차감하지 않는다.
- 선택 문자열이 남은 수량으로 구성되면 입력할 수 있다. 수량이 부족해도 미완성 정답의 접두사인 동안은 입력을 허용한다.
- 글자를 추가할 때 전체 문자열을 재검사한다. 이미 채운 교차 글자나 힌트 글자는 재사용할 수 있으며 랙 수량에 다시 더하지 않는다.
- 랙의 `↻` 표시는 수량을 넘겨 정답 글자를 재사용할 수 있다는 뜻이다. 표시 숫자는 0 미만이 되지 않는다.
- 웹에서는 스와이프로 제출하거나 글자를 차례로 누른 뒤 입력 단어를 눌러 제출한다. 입력 단어에 포커스한 상태에서 Enter/Space로도 제출한다.

### 2. 보너스 단어
- 보드 정답이 아닌 유효 단어를 제출하면 보너스 처리한다.
- 보너스 단어는 코인을 주지만 보드 상태는 바꾸지 않는다.
- 보너스는 현재 남은 수량으로만 입력할 수 있으며 정답 접두사 예외는 적용하지 않는다. 정답과 같은 단어나 이미 받은 보너스에는 보상을 주지 않는다.

### 3. 저장
- 현재 레벨
- 보유 코인
- 소리 on/off
- 채워진 좌표
- 찾은 보너스 단어
- 현재 레벨의 클리어 보상 지급 여부. 기존 localStorage 저장 키와 오프라인 실행을 유지한다.

### 5. Godot 입력 연결
- `SwipeRackController.level_controller`를 인스펙터에서 지정하거나 `set_level_controller(controller)`로 연결한다. 기존 `current_letters`, `word_changed`, `word_submitted`, `append_letter`, `submit`, `clear_selection` 인터페이스를 유지한다.
- 랙의 `word_changed` 신호마다 `현재 문자열 + 타일 글자`를 `LevelController.can_select_text()`로 검사한다. 각 타일에 `set_remaining()`을 호출한 뒤 `set_selectable(선택 가능 여부, 재사용 표시 여부)`를 호출한다. 표시 수량과 입력 허용 여부는 별개다.
- `LetterTile`은 기존 Button 기반이며 `setup_tile(letter, count)`, `set_remaining(count)`, `tile_selected`를 유지한다. `set_remaining()`은 이전 선택 허용 상태를 기본 수량 규칙으로 초기화하므로 호출 순서를 지킨다.
- 힌트·로드·레벨 전환 시 `clear_selection()`을 호출하고 타일 상태를 새로 계산한다. `can_submit_bonus()`는 단어 목록·수량만 검사하므로 호출자가 발견 목록과 중복 보상도 검사해야 한다.
- MainGame 씬과 실제 연결을 구현했다. Godot 4.7.2 실행 및 저장·입력 회귀 검사 범위는 `GODOT_PLAYABLE.md`에 기록한다. iOS 실기기 검증은 후속 작업이다.

### 4. UX 목표
- 힐링 톤의 밝은 UI
- 모바일 세로 화면 우선
- 실수 취소가 자연스러운 스와이프
- 정답/보너스에 명확한 피드백

# Gemini: v1 아트·문구·콘텐츠 첫 묶음

## 그대로 복사할 요청

```text
Word Tiles iOS 출시용 아트 명세 보완, ko/en/ja UI 문구, 언어별 단어·초기 레벨 묶음을 제작하라. 함께 첨부한 gemini-launch-content-source.txt는 ZIP이 아닌 UTF-8 일반 텍스트다. FILE BEGIN/END 사이의 원문을 먼저 읽어라.

저장소 문서 docs/LAUNCH_SCOPE.md와 docs/VISUAL_DIRECTION.md가 이번 작업의 기준이다. 외부 game-studio, HubGame, 웹 리더보드, 3D 아키텍처 지침을 가져오지 마라. 런타임 코드와 저장 함수를 수정하지 마라. Godot 오프라인 iOS 게임이며 웹 코드는 규칙 검사용이다.

이미 확정한 조건:
- 밝은 2D 단어 정원, 종이·무광 타일·자연 풍경. 그래픽 실제 제작은 나중이다.
- ko/en/ja 각각 일반 450+일일 30이 최종 목표다. 이번에는 아래 첫 묶음만 만든다. 반복 보드를 수량으로 채우지 마라.
- UI 언어와 퍼즐 언어는 분리한다. ko는 조합 한글, en은 A-Z, ja는 NFC 히라가나를 사용한다. 동일 단어를 단순 번역해 같은 교차 좌표에 넣지 마라.
- 미완성 정답은 출시 UI에서 숨긴다. 구매·광고 없이 풀이 가능해야 한다. 강제 과금 유도·가짜 긴급성은 쓰지 마라.

원문을 읽었다는 확인으로 현재 MainGame의 UI 생성 함수 이름, 실제 ConfigFile 저장 경로, 현재 정답 보상 산식을 먼저 짧게 적어라. 기준안과 기존 코드가 다른 것은 정상이며 코드를 임의 수정하지 마라. 파일을 읽을 수 없다면 필요한 경로만 요청하라.

이번 산출물(정확한 경로별 전체 내용, 생략·의사코드·샘플 표기 금지):
1. content-staging/gemini-v1/ART_BRIEF.md
   고정 방향을 유지한 6개 배경·타일 5상태·아이콘 16종·스탬프 6개·앱 아이콘의 제작 지시와 이미지 생성 프롬프트. 이미지 안에는 문자·가격·UI를 넣지 않는다. 크기·안전 여백·투명도·파일명은 asset_manifest.json과 일치시킨다. 실제 이미지를 만들지 않았다면 명세라고 명시한다.
2. content-staging/gemini-v1/ui_strings.json
   {"schema_version":1,"strings":[{"key":"...","ko":"...","en":"...","ja":"...","context":"...","max_chars":N}]} 구조. UI 문구는 최소 70개 키로, 홈/설정/음악/효과음/음량/퍼즐 언어/앱 언어/진행/정답/보너스/힌트/3단계 튜토리얼/일일/상점/광고/구매/복원/보류/오프라인/오류/저장 실패를 포함한다. {count}, {coins}, {price} 등 이름 있는 자리표시자의 집합은 세 언어에서 정확히 같아야 한다. 짧고 자연스럽게 쓰고 가격은 만들어 넣지 마라. 교차 재사용은 정답에만 허용된다고 설명하라.
3. content-staging/gemini-v1/wordbank_ko.json, wordbank_en.json, wordbank_ja.json
   각 {"schema_version":1,"locale":"ko|en|ja","review_status":"unreviewed","entries":[{"id":"ko_word_0001","word":"...","meaning":"해당 언어로 쓴 짧은 뜻","theme":"garden|forest|sea|cafe|sunset|greenhouse","familiarity":1,"notes":"검수 이슈 또는 빈 문자열"}]} 구조. 언어별 서로 다른 단어 80개를 만든다. familiarity는 1(매우 친숙)~5(어려움) 정수. ko 2~5음절 명사, en 3~7자 명사 중심, ja 2~6자 히라가나 명사. 고유명사·상표·비속어·희귀 활용형·억지 음역은 제외한다. 쉬운 단어의 자연스러운 재사용은 허용하되 한 단어로 모든 보드를 채우지 않는다. 원어민 검수·사전 라이선스를 허위로 주장하지 마라.
4. content-staging/gemini-v1/levels_ko_001_015.json, levels_en_001_015.json, levels_ja_001_015.json
   각 파일은 기존 levels.json과 같은 배열이며 항목은 기존 theme, rows, cols, difficulty, words:[{word,r,c,dir}], bonusWords를 유지하고 id, locale, chapter, theme_id를 추가한다. id는 ko_main_0001 식의 고정 ID. 15개씩 만들고 위 wordbank 안의 단어만 사용한다. 최대 7×7·고유 랙 글자 10종, 처음 5개는 2단어·나머지는 3단어 중심이다. 모든 정답은 교차 관계로 연결되어야 하며 교차 글자는 같아야 한다. 같은 선상 단어 겹침·완전 포함·끝에 붙는 의도하지 않은 단어·같은 방향 인접 단어를 피한다. 모든 보드는 서로 달라야 한다. 보너스는 정답과 다르고 초기 빈 셀 수량으로 구성 가능해야 한다. 적절한 보너스가 없으면 []로 둔다. 450개 전체를 생성했다고 쓰지 마라.
5. content-staging/gemini-v1/REVIEW_NOTES.md
   실제 산출 수, 어휘 불확실성·라이선스 확인 필요, 실행한 검사와 미검증을 구분한다. 로컬 실행 권한이 없으면 배치·중복·Unicode·엔진 검사는 Codex가 수행할 미검증 항목으로 적는다. 읽지 않은 파일이나 실행하지 않은 코드를 검증했다고 쓰지 마라.

코드 블록 앞에 정확한 경로를 적고 각 파일을 끝까지 출력하라. 응답 길이가 부족하면 완성한 파일까지만 반환하고 다음 파일 경로를 명시하라. 파일 중간 생략이나 ...를 넣지 마라. 결과는 아직 검수되지 않은 staging 자료이며 출시 승인본이 아니다.
```
